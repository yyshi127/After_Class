# AfterClass 商用上线风险清单

状态口径：

- 已处理：MVP 已有机制或文档/测试覆盖，可进入试点上线。
- 人工复核：系统提供数据和留痕，但上线初期必须人工确认。
- 暂缓：不阻塞 MVP 试点，但不得对外承诺已自动化完成。

| 风险 | 等级 | 状态 | 处理方案 | 上线前验收 |
| --- | --- | --- | --- | --- |
| 数据备份缺失导致学生档案、照片、作业反馈丢失 | 高 | 已处理 | `scripts/backup.sh` 覆盖 PostgreSQL dump 与 `STORAGE_PATH` 文件归档；`docs/operations/backup-and-restore.md` 说明恢复流程 | 至少完成一次备份与恢复演练，备份文件异地加密保存 |
| 未成年人隐私泄露：身份证、手机号、照片、作业原图 | 高 | 已处理 | 家长/学生端最小化展示；身份证默认脱敏；普通日志禁止打印敏感字段；私有文件目录不入 Git | 抽查家长/学生端页面与日志，无身份证号、手机号、私有文件路径泄露 |
| 图片/作业资料授权不清 | 高 | 人工复核 | 机构上线前需在入托协议/隐私政策中补充照片、作业图片、AI 辅助批改和家校反馈用途授权 | 试点机构提供签署版本；未授权学生不得使用照片/作业图片 AI 功能 |
| AI 自动化误判影响学生评价或家校关系 | 高 | 已处理 | AI 仅输出草稿/建议；错因、反馈、练习单、请假动作均保留老师/家长确认；高风险收费/投诉类动作拒绝 | 演示并验证确认/取消/拒绝路径，不允许 AI 直接执行高风险动作 |
| 收费、欠费、课消、老师费用、毛利误展示给家长 | 高 | 已处理 | 家长端只展示服务有效期/续费指导；内部财务字段仅管理员可见；E2E 覆盖角色隔离 | 家长端搜索不得出现余额、欠费、应收、已收、课消、教师费用、毛利 |
| 收费调整、退费、欠费清零缺少人工复核 | 高 | 人工复核 | 系统保留管理员收费页与审计日志；上线初期收费变更必须线下双人复核 | 每笔收费调整记录 actor、reason、target 和复核人；AI 不执行欠费清零 |
| 跨校区/跨角色越权访问 | 高 | 已处理 | RBAC + 校区/学生/家长绑定过滤；核心页面和 E2E 覆盖权限隔离 | 用校区管理员、老师、家长、学生账号交叉验证不可见越权数据 |
| Docker/Compose 在目标服务器未实测 | 中 | 暂缓 | 当前开发环境无 Docker；已完成静态测试、Next build 和部署文件；需在实际服务器执行 `docker build` / `docker compose up` | 上线服务器完成镜像构建、容器启动、健康检查和迁移 seed 演练 |
| 日志过度采集或保留过久 | 中 | 已处理 | `docs/operations/logging-strategy.md` 定义应用/AI/审计/错误日志分层、必填字段和保留期 | 抽查 stdout 与数据库日志，确认普通日志无敏感明文 |
| AI Provider 不稳定或成本超预期 | 中 | 暂缓 | AI Provider 可插拔；MVP 保留人工流程兜底；上线初期限制 AI 调用入口与频率 | 配置调用限额、错误提示和人工处理流程；每周复盘 AI 成本 |
| 备份包含生产隐私数据后被提交或外泄 | 高 | 已处理 | `/backups`、`/storage` 已加入 `.gitignore`；备份建议加密异地保存 | Git 状态检查不得出现备份包、学生照片、作业图片 |
| 缺少正式合同、价格、SLA 和售后流程 | 中 | 暂缓 | 不属于软件 MVP 代码范围；试点前需要商务模板和支持流程 | 首个付费试点前补齐合同、报价、服务边界、故障响应窗口 |

## 上线 Go / No-Go 结论

- 可进入小范围试点的前提：完成真实服务器 Docker/Compose 验证、至少一次恢复演练、机构授权文本确认、收费调整人工复核流程落地。
- 不建议直接大规模商用：AI Provider 稳定性、合同/SLA、正式运维监控和恢复演练还需要在真实环境跑通。
- 禁止承诺：AI 全自动批改替代老师、自动收费/退费/欠费清零、无人工审核的严重学情判断。
